# pi-private

`/private` launches a fresh Pi session in a sibling Herdr tab (tmux window when outside Herdr). `/private nohistory` launches with **no history-search extension** and no optional extensions. To expose the command in a parent Pi process, load `pi-private/index.ts` with `-e` or install this package normally; neither is done automatically by this repository. Standalone terminal: `bun pi-private/cli.ts [nohistory]` (run from this checkout). No parent conversation is forked or copied.

## Isolation and allowlist

Both profiles use `pi --no-extensions --no-mcp --no-skills --no-prompt-templates --no-themes --no-context-files --tools read,bash,edit,write` plus explicit `-e` paths. Built-in MCP, codemode, tool-search and configured/discovered extensions are not loaded implicitly. The **default explicit allowlist for `/private`** is this extension plus the trusted sibling `pi-history-search/index.ts`; if that file is absent, `/private` fails before launching. Optional additional extensions or a different history-search path can be allowlisted in `~/.config/pi-private/config.json` (0600). See `private.example.json` and `private.schema.json`. Keys are identifiers, values absolute entry-file paths or supported `builtin:<name>` entries (e.g. `"codemode": "builtin:codemode"`). `/private nohistory` ignores all optional extensions including history-search, even if configured. Its only `-e` is pi-private itself. Do not add an extension that starts background services, searches external history, or exports transcripts unless you have reviewed it.

Sessions go under `~/.local/share/pi-private/sessions/<profile>-<random>/` (or `$XDG_DATA_HOME/pi-private/sessions/`); override with absolute `sessionRoot` outside `~/.pi/agent`. The private root, per-session directory and Atuin config are 0700. Standard ancestors such as `~/.local/share` may have normal permissions, but symlinked ancestors are refused. `PI_CODING_AGENT_SESSION_DIR` points at the isolated session directory so nested Pi processes that inherit the child environment do not silently fall back to normal storage. Explicit `--session-dir` flags and Herdr subagents that start in fresh tabs can still override or lose this setting; do not delegate private transcripts without a verified propagation policy. `KOMPRESS_ROLLING=0` is passed to the child; there is no rolling capture in this profile. Herdr receives environment through `tab create --env` and Pi args through `agent start -- ...`. The caller workspace is required; no focused-workspace fallback. In tmux, `new-window` uses an exec command. Plain terminal launches directly, without an interactive shell. The launcher and its 0700/0600 permission checks have been exercised on macOS; Linux and native Windows (including `.cmd` launcher handling and ACL enforcement) have not yet been verified. Do not treat this as a Windows security guarantee.

Resuming is deliberate: from another shell run `bun pi-private/cli.ts [nohistory] --resume /absolute/path/to/the/profile-directory`. The launcher checks the directory and profile, then uses `--continue` with that exact `--session-dir`; do not use the parent Pi's `/resume`, which points at its own sessions. Remember the printed directory. Fresh launches never resume a previous private session.

The child shell gets a per-session Atuin config excluding all history entries (`history_filter = [".*"]`) and `HISTFILE=/dev/null`, `HISTSIZE=0`; this prevents the Herdr child shell from recording its Pi launch with the normal Atuin hook. In a plain terminal, the *calling shell* may record the standalone `bun pi-private/cli.ts` command before the child can set these variables. Use a history-free calling shell if that matters. None of these commands include credentials. This does **not** prevent terminal scrollback, shell wrappers ignoring these variables, bash commands run later by Pi, provider logs, OS swap, filesystem backups, tools writing elsewhere, or other user-level software from retaining data. The built-in bash tool can still execute search commands; nohistory means *no history-search or search-named tool is loaded*, not an OS-level ban on searching files. Pi commands such as export/share remain available: do not use them for sensitive sessions. Avoid running from a sensitive cwd if tools can read it.

## Encryption status: not a live-session guarantee

**Session files remain plaintext while Pi runs and after it exits. Password-protected encryption and YubiKey-gated unlock are NOT implemented.** Do not use this as an at-rest encrypted private mode. The optional `archive.ts` helper is only a manual *offline export* using age's public-recipient (`-r`) mode; no password is placed in argv or env. `bun pi-private/archive.ts encrypt SESSION_FILE AGE_PUBLIC_RECIPIENT OUTPUT.age` archives one file without removing the plaintext. `bun pi-private/archive.ts decrypt ARCHIVE.age IDENTITY_FILE OUTPUT` uses age `-i` (which may support plugin identities if age and the plugin are installed), writing only into a private destination directory. It refuses to overwrite, rejects insecure inputs, and discards partial output on failed unlock. The identity *path* (not key material) appears in the process command line. Neither age nor any YubiKey plugin is bundled; actual interoperability is not verified here. A crash can leave plaintext, including temporary partial decrypts; deletion is not secure erasure on SSDs. No automatic sealing, secret prompt, encryption at rest while live, or cleanup after a crash is promised. If encrypted sessions are required, do not launch until a separately reviewed end-to-end encryption backend exists.

## Verification

`bun test pi-private/launch.test.ts` includes real Pi RPC boot tests proving `/history` exists only in the standard profile, isolation of the session path, Herdr argument/environment propagation via a test double, permissions and failed age unlock cleanup. `bun run check` runs repository-wide lint/typecheck; report any unrelated baseline failures separately. No global Pi configuration or machine installation is changed by this package.
